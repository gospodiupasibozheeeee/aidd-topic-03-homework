## Корректировки и возникшие проблемы

1. **Изоляция ветки.** Пользователь отдельно потребовал: «все изменения делай в
   отдельной своей ветке» и «AGENTS.md так же перенеси в свою, локальную ветку».
   Результаты сохранены в `codex`; в общую ветку изменения не переносились.
2. **Общая рабочая копия.** Во время модернизации внешние переключение ветки и
   очистка дерева затронули незакоммиченные результаты. Codex восстановил изменения
   в отдельном worktree и продолжил там. Правильная первоначальная организация —
   отдельная копия сразу, как предписывает `HOMEWORK.md`.
3. **Ложное предположение анализа.** Различие написания `blank=True` у поля
   `auto_now` было сначала сочтено миграционным расхождением. Проверка состояния
   Django показала, что `auto_now` устанавливает параметр автоматически.
   Предположение снято, объяснение сохранено в `ANALYSIS.md` и `AUDIT.md`.
4. **Окружение запуска.** Docker CLI отсутствовал. Для проверки PostgreSQL/Redis
   использованы временные экземпляры локальных сервисов, без изменения задания
   на проверку только SQLite. Подробности и версии зафиксированы в `AUDIT.md`.
5. **Внешние данные.** Настоящий Tinkoff-токен не предоставлялся. Проверки адаптера
   и полной фоновой цепочки использовали синтетический рыночный HTTP-сервер.
   Успешный запуск приложения не выдаётся за проверку реального банковского доступа.
6. **Инструментальные разрешения.** На раннем этапе отдельные Git-операции требовали
   разрешений среды; это не уточнения бизнес-требований. Они не дают основания
   считать число вмешательств разработчика равным числу команд терминала.
7. **Проверочный адаптер задания №5.** Первый пробный запрос к Antigravity использовал
   `portfolios` вместо зарегистрированного `portfolio` и получил 404. Маршрут сверен
   с router, исправлен; свежий повторный прогон подтвердил настоящий ответ 500 на
   некорректное количество. Итоговый JSON содержит исправленный эксперимент.

У Antigravity независимая проверка выявила неверный REST-путь банка, ошибки 500,
потерю истории и отсутствие валютной проверки. У DeepSeek — недоступность SDK на
Python 3.14, изменение regex-контракта поиска, потерю истории и несогласованный
журнал стратегии при устаревшем состоянии объекта. Это ошибки результатов,
подтверждённые кодом/пробами; они не доказывают, какие подсказки давал пользователь
и сколько попыток предпринимал агент. Точные свидетельства приведены в сравнении.

## Как проверялись результаты

- Задания №1–2: чтение моделей, форм, сериализаторов, URL, шаблонов, задач,
  миграций и исходных тестов; требования связаны с кодом базового `362510b`.
  Первые документы явно обозначают статический характер проверки.
- Задание №3: запуск HTTP, тесты и проверки Django, работа с PostgreSQL, Redis,
  Worker и Beat; найденные дефекты отделены от новых возможностей.
- Задание №4: штатные тесты, проверки собственника и CSRF, транзакционные сценарии,
  графики/история, мониторинг и торговля; 104 теста на PostgreSQL, 100 успешных и
  4 пропущенных на SQLite, по 41 сквозной проверке на каждом backend.
- Задание №5: одинаковая версия Python и изолированные SQLite для трёх коммитов;
  установка собственных зависимостей, тесты, покрытие, миграции, настоящий HTTP,
  11 дополнительных сценариев. Подробные результаты —
  [audit/comparison.json](audit/comparison.json).

## Время, итерации и ограничения

По Git между первым и последним коммитами заданий №1–4 прошло: Codex —
2 ч 26 мин 40 с (4 коммита), Antigravity — 56 мин 32 с (5 коммитов), DeepSeek —
33 мин 32 с (4 коммита). Даты и метод приведены в `COMPARISON.md`.
Это календарные интервалы публикации результатов, не активное время решения.

Число коммитов не равно числу итераций генерации. Точное количество инструментальных
вызовов, внутренних исправлений, токенов и длительность ожидания по всем трём
участникам не измерялись. Для Codex подтверждены два дополнительных указания
пользователя об организации ветки; для других участников счётчик уточнений
неизвестен. Данных об исчерпании бесплатной квоты и фактической стоимости нет.

Практический результат: все три приложения воспроизводимо запускаются в общей
среде, но прохождение собственных тестов не гарантирует сохранность финансовых
данных и работоспособность внешней интеграции. Поэтому сравнение опирается также
на независимые сценарии и конкретные ограничения, перечисленные в `COMPARISON.md`.
