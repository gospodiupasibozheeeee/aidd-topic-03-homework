## 3. Task 1. Анализ исходного кода

### DeepSeek

- `ANALYSIS.md`: **1400 строк**, 99 КБ.
- Покрыты назначение, стек, структура, архитектура, Mermaid-диаграммы компонентов и
  последовательностей, зависимости, модель данных, URL-карта, ORM, транзакции,
  Celery, Tinkoff, дефекты и выводы.
- Есть точные ссылки на файлы и строки, таблицы полей и маршрутов.
- Обнаружена и позже исправлена фактическая ошибка: `search_fields = ["$name"]`
  был описан как prefix-поиск, хотя DRF использует `$` как regex (`iregex`).
  Исправление внесено в Task 3; это пример полезности последующей проверки.

### Codex

- `ANALYSIS.md`: **232 строки**, 31 КБ; плюс `AGENTS.md` (45 строк) и
  `audit/dependencies.json`.
- Анализ плотный: назначение, стек, структура, архитектура, модель, HTTP/ORM,
  рыночные данные, ограничения и границы подтверждённости.
- Явно отделены факты от предположений; указано, что приложение и API не запускались.
- Меньше иллюстраций и таблиц, чем у DeepSeek/Antigravity, но высокая
  информационная плотность; позже дополнен `AUDIT.md` с фактической проверкой.

### Antigravity

- `ANALYSIS.md`: **1541 строка**, 114 КБ — самый объёмный анализ.
- Максимальная детализация структуры, слоёв, данных, URL, запросов, зависимостей и
  дефектов; большое количество таблиц и диаграмм.
- Сильная сторона — полнота; слабая — избыточность и большая стоимость чтения.

**Вывод по Task 1:** Antigravity — максимальная полнота; DeepSeek — лучший баланс
полноты и структуры; Codex — самый компактный и «инженерный» анализ с явными
границами и последующим аудитом.

## 8. Ошибки, проблемы и ограничения

### DeepSeek

- Первоначально был сделан коммит в ветку `antigravity`; потребовалась коррекция
  пользователя и перенос результата в `deepseek`.
- В Task 1 допущена фактическая ошибка о `$name` (regex vs prefix); исправлена в Task 3.
- Нет live PostgreSQL/Redis/Tinkoff; Task 4 API не добавлен.
- Нет coverage/pip-audit; проверка ограничена тестами и smoke-запуском.

### Codex

- Task 4 реализован, но **не закоммичен**: 22 изменённых/новых файла, `investing/`,
  `FEATURES.md`; в ветке `codex` есть только Task 1–3.
- Собственный REST-клиент Tinkoff вместо SDK — плюс для Python 3.14, но дополнительная
  зона ответственности и рисков.
- При нашем запуске тестов в его рабочем дереве возникла ошибка записи `app.logs`
  из-за прав/file sandbox; независимо запущены только 59 коммитных тестов.
- Coverage 95%, pip-audit и PostgreSQL/Redis заявлены в `AUDIT.md`; мы их не
  перепроверяли.

### Antigravity

- Нет отдельного `AUDIT.md`, coverage и pip-audit; проверка — 49 тестов.
- Очень большой объём документации (1541 + 407 строк) и 6856 добавленных строк:
  выше стоимость сопровождения.
- Task 4 встроен в `dashboard`, а не в отдельное приложение; выше связность.

## 9. Выводы

### 9.1. Основная пара: DeepSeek vs Codex

- **Task 1–2:** DeepSeek даёт более полные и структурированные документы
  (45 ФТ, 58 правил, 25 дефектов, трассируемость); Codex — компактнее, но с
  отдельным аудитом и явными границами.
- **Task 3:** Codex существенно сильнее по инженерной доказательности
  (59 тестов, coverage, pip-audit, PostgreSQL/Redis, runtime-проверки).
  DeepSeek быстрее и проще, но проверяет меньше.
- **Task 4:** DeepSeek сдал все четыре функции в ветке; Codex спроектировал
  более сильную реализацию (25 НФ, 9 моделей, 44 теста, API, идемпотентность),
  но не закоммитил её. По критерию «работоспособное приложение с новой
  функциональностью» результат DeepSeek завершён, Codex — нет.
- **Итог:** если важнее **глубина инженерии и проверок** — Codex; если важен
  **завершённый, сохранённый в ветке результат всех четырёх задач** — DeepSeek.

### 9.2. Пара Codex vs Antigravity

- Codex лучше по Task 3: тесты, coverage, аудит зависимостей, реальные
  PostgreSQL/Redis, runtime-сценарий.
- Antigravity лучше по завершённости Task 4: все функции закоммичены, API и UI
  расширены, 26 тестов Task 4; Codex Task 4 не сдан.
- Документация Antigravity объёмнее; документация Codex компактнее и
  верифицируемее.
- **Итог:** Codex — качество и проверяемость Task 1–3; Antigravity — полнота
  сданного решения Task 1–4.

### 9.3. Пара DeepSeek vs Antigravity

- Оба завершили все четыре задачи и закоммитили результат.
- DeepSeek: 63 теста, отдельное приложение `investments`, быстрее, проще,
  лучше трассируемость требований; нет API новых функций и live-интеграций.
- Antigravity: 49 тестов, API новых функций, больше документации и интеграции;
  меньше измерений и выше связность.
- **Итог:** DeepSeek — скорость, тесты, модульность; Antigravity — охват API/UI и
  объём документации.

### 9.4. Общий вывод

Ни один агент не является лучшим во всём:

- **Codex** — лучший выбор для аудита, тестирования, покрытия, конкурентности и
  инженерной строгости; главный недостаток — незавершённая сдача Task 4.
- **DeepSeek** — лучший выбор для быстрого доведения всех четырёх задач до
  работающего, закоммиченного состояния с хорошим тестовым покрытием.
- **Antigravity** — лучший выбор, если нужны максимально подробная документация,
  расширенный API и полная интеграция функций в существующее приложение.

Для учебного задания, где обязательны **все четыре задачи и сохранение результата
в ветке**, наиболее сбалансированы **DeepSeek** и **Antigravity**; для задачи
«провести глубокий аудит и доказать качество модернизации» — **Codex**.
