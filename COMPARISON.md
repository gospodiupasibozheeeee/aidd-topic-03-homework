# Сравнение результатов AI Coding Agents

## Объект и метод проверки

Задание №5 выполнено 1 ноября 2026 года. В репозитории доступны три завершённые
реализации, поэтому сравнение охватывает **Codex, Antigravity и DeepSeek**.
Это названия веток и участников эксперимента; точные модели и тарифы по Git
установить нельзя. Выводы относятся к данным реализациям одного проекта.

Исходная версия для всех — `362510b`. Проверены неизменяемые снимки после задания №4:

### Внешняя интеграция и конфигурация

REST-клиент Antigravity вызывает `tinkoff.public.invest.api.v1.InstrumentsService/Shares`
без сегмента `contract` (`6ef049a:dashboard/services/client.py:53`). В опубликованном
[OpenAPI Tinkoff Invest](https://github.com/Tinkoff/investAPI/blob/main/src/docs/swagger-ui/openapi.yaml)
задан путь `tinkoff.public.invest.api.contract.v1.InstrumentsService/Shares`.
Локальный сервер, принимающий этот контракт, вернул Codex один инструмент;
Antigravity получил 404 и превратил ошибку в пустой результат. Проверялось
соответствие опубликованному пути; запрос с настоящим токеном в банк не выполнялся.

В DeepSeek `requirements.txt:17` устанавливает SDK только при Python < 3.12.
На общем Python 3.14 он закономерно отсутствует; `_load_client_class()` сообщает
о недоступности интеграции. Приложение запускается, но одного токена для импорта,
внешних свечей и обновления цен в этой среде недостаточно. Проверка других версий
Python и реального банковского доступа не выполнялась.

Все участники перешли на Django 5.2.18, DRF 3.18.3 и Celery 5.6.3. У Antigravity
диапазоны зависимостей разрешились в Plotly 7.1.0 и Redis client 8.1.0; у остальных
зафиксированы 6.9.0 и 6.4.0. Это риск воспроизводимости, а не доказательство
несовместимости: установка и тесты прошли. У Codex есть транзитивный lock-файл,
у DeepSeek фиксированы прямые версии.

При `DEBUG=False` и отсутствии ключа Codex и DeepSeek прекращают запуск понятной
ошибкой; Antigravity генерирует новый `SECRET_KEY` при загрузке процесса
(`6ef049a:config/settings.py:12`), что создаёт риск несовместимых сессий между
процессами. Это вывод из конфигурации; многопроцессный production-запуск не измерялся.

Интервалы Git не включают работу до первого коммита, включают ожидание пользователя
и работу инструментов, зависят от стратегии коммитов. Они **не устанавливают**, что
DeepSeek работал быстрее Codex в соответствующее число раз. Штатные тесты здесь
запускались параллельно; их длительность также не сравнивает скорость агентов.

В видимой сессии Codex сам исследовал проект, реализовал задания и проверил сервисы.
Однако изначальная работа в общей копии привела к потере незакоммиченных изменений
при внешнем переключении/очистке дерева. Результат восстановлен в отдельном
worktree `aidd-topic-03-homework-codex`. Изоляцию следовало обеспечить раньше;
это организационная ошибка, а не свойство алгоритма другого агента.
Описание промптов, корректировок и проверки — [REPORT.md](REPORT.md).

Полных журналов Antigravity/DeepSeek, идентификаторов моделей, числа повторных
запросов, отказов по квотам и платёжных данных нет. Их самоотчёты полезны как
вторичный источник, но не подтверждают эти показатели независимо. Бесплатные
лимиты, доступность без карты и кроссплатформенность инструментов в данном
эксперименте не проверялись. Исследовался только macOS.

В `09251ac:COMPARISON.md` DeepSeek описывает ещё незакоммиченный этап №4 Codex.
Его отчёт создан в 22:30:48, а `68ad48e` — в 22:34:12. Это разные моменты
наблюдения; текущая проверка использует завершённый коммит. Такой старый вывод
нельзя переносить на настоящий снимок без повторной проверки.

## Выводы по практическим результатам

- **Codex** дал наиболее полную проверку целостности из сопоставленных результатов:
  сохранил финансовую историю при удалении акции, проверяет валюту, повтор котировки
  и неизвестную оценку. Полезен для задач с HTML/API и транзакционными ограничениями.
  Цена этого подхода в данном опыте — более длинный календарный интервал, большой
  объём проверок и необходимость исправить собственную организацию рабочего дерева.
- **Antigravity** реализовал широкий интерфейс в существующем приложении и два типа
  стратегии. Такой результат удобен для демонстрации пользовательских сценариев.
  До использования рыночной интеграции и финансовых расчётов необходимы исправления
  REST-пути, ошибок 500, валютных проверок и удаления истории; 49 зелёных тестов их
  не обнаружили.
- **DeepSeek** выделил предметную область, использовал типизированные расчёты,
  поддержал дробные количества и явно описал ограничения. Такой вариант подходит
  для учётного прототипа с HTML-интерфейсом. На выбранном Python требуется решение
  для SDK; нужны защита журнала, согласование стратегии при повторных исполнителях
  и корректная трактовка отсутствующей цены.

В этом проекте Codex лучше подтвердил сохранность данных, Antigravity предложил
больше вариантов стратегии, DeepSeek — дробный учёт и ясное разделение сервисов.
Это вывод о конкретных проверенных версиях, а не универсальный рейтинг моделей.
Ни у одного участника реальный рыночный доступ данным сравнением не подтверждён.

## Воспроизведение

Из ветки `codex`, при наличии трёх указанных Git-коммитов и доступа к PyPI:

```sh
python scripts/compare_branches.py
# Повторный запуск в сохранённых экспортированных снимках:
python scripts/compare_branches.py --snapshot-root /path/to/exported-snapshots
```

Скрипт печатает результаты и сохраняет JSON; журналы команд остаются во временных
снимках в `comparison-*.log`. Повторный запуск очищает только их синтетическую
`evaluation.sqlite3`. Реальные токены и `.env` рабочих копий не используются.
Из-за незакреплённых транзитивных зависимостей двух веток будущие установки могут
разрешиться иначе; фактически установленные версии сохранены в JSON.
